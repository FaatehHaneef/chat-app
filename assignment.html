What to submit

  2. A Loom walkthrough. Max 4 minutes, your face visible throughout. ~1 minute introducing yourself, then walk us through the app — features, design decisions, and code.
  3. Your agentic logs — as a zip. The full record of how you worked with AI to build this. This is required, and it's a big part of how we evaluate you. Details below.

Your agentic logs — the most important part

Building with AI is the job. We don't just want to see the finished app — we want to see how you got there: how you prompt, how you steer an agent, how you catch its mistakes, how you make decisions. So we ask every applicant to capture and submit their full agentic logs: every prompt you sent your AI/coding agent, and the responses it gave, across the whole build.

No logs = incomplete application.

If you submit an app with no agentic logs, we can't evaluate how you work, and we won't move forward. Set up logging before you start building — not the night before you submit.

How it works

Don't ask your agent to "remember to log" — that's unreliable and easy to fake afterward. Instead, capture what your AI tool already records: its raw session transcript. A small script reads that transcript after every turn and writes a clean markdown copy into a .claude-logs/ folder in your repo. This is exactly how we capture logs internally, and it works whether you build with Claude Code or Codex.

Easiest path: paste the one-shot setup prompt below to your agent at the very start, before you build anything. It downloads the capture scripts, wires them to run after each turn, and verifies they work. Prefer to wire it by hand? Grab the scripts directly: extract-log.py (Claude Code) · capture-codex-session.mjs (Codex).

One-shot setup — paste this to your agent first

Set up automatic agentic-logging for this project before we build anything. My
full prompt + response transcript is part of a job application for 8x and must
be captured to a .claude-logs/ folder and committed to the repo.

You might be running as Claude Code OR as Codex — set up whichever you are:

1. Create a scripts/ folder and download both capture scripts into it:
     curl -fsSL https://8x-internal.com/join/play-engineer/logging/extract-log.py \
       -o scripts/extract-log.py
     curl -fsSL https://8x-internal.com/join/play-engineer/logging/capture-codex-session.mjs \
       -o scripts/capture-codex-session.mjs

2. If you are CLAUDE CODE: create or merge .claude/settings.json so a Stop hook
   runs "python3 scripts/extract-log.py" after every turn (Stop hooks fire when
   you finish responding).

3. If you are CODEX: add a "logs:capture" script to package.json that runs
   "node scripts/capture-codex-session.mjs", and wire your notify/stop hook (or
   ~/.codex/config.toml notify) so it runs after each turn.

4. Create the .claude-logs/ folder, run the capture once now, and show me the
   newest file inside it so we can confirm a real transcript was written.

5. Add .claude-logs/ to git — do NOT gitignore it. These logs are my submission.

Do all of this now, then tell me the exact command I can run anytime to confirm
new logs are landing after each turn.

Verify it's actually working (check on day one)

Don't trust it blindly. After a few turns, confirm real transcripts are landing:

  • Open the newest file in .claude-logs/ — it should hold your actual prompts and the agent's responses.
  • Count how many log files exist; it should grow as you build:
ls -1 .claude-logs/*.md | wc -l

If .claude-logs/ is empty or missing, logging isn't wired up — fix it before you keep going. Logs reconstructed at the end are obvious, and they don't count.

Submit them as a zip

When you're done, zip your .claude-logs/ folder and upload the .zip in the application form. (It's also committed in your repo — but the zip is what we open first.) 

# from your repo root
zip -r claude-logs.zip .claude-logs/
